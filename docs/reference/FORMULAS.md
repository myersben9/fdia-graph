# Formulas: from the equation in the source to the function in the code

Every operation in the package that appears in a paper or a textbook gets one named function,
even when it is called once, so a reader can go from an equation to the code and back. This
catalogue is the index: one row per formula, the function that implements it, the equation in
plain text, the source with a key from [`REFERENCES.md`](REFERENCES.md), and where it is used.

A formula is a pure function in a `formulas/` package, cited here once, and the rest of the code calls it
rather than repeating the expression. A new formula function gets its row here in the same change.

Each toolkit has its `formulas/`. The generation toolkit's (`fdia_graph.formulas`) holds what the
generator and the loader compute: the network model (`formulas.network`), the meter noise
(`formulas.noise`), the attack shapes (`formulas.attacks`), the temporal features
(`formulas.temporal`) and the row reduction of the attack search (`fdia_graph.formulas.trust`). The
analysis toolkit's (`fdia_analysis.formulas`) holds the rest: estimation (`formulas.estimation`,
`formulas.linalg`, and the estimator's measurement function in `formulas.measurement`), the Jacobian
projections (`formulas.projection`), the metrics (`formulas.metrics`), the federated statistics
(`formulas.federated`) and trusted-meter selection (`fdia_analysis.formulas.trust`). A row below names
a function by its module, which is in one toolkit only; the two `trust` modules are named with their
toolkit.

## How a formula function is written

```python
def swing_zscore(nx: np.ndarray, prev: np.ndarray, scale_t: np.ndarray, metered: np.ndarray) -> np.ndarray:
    """The one-step injection change as a z-score of the bus's typical recent change [FED26], [N, 2]
    float32, dimensionless: swing[b] = ([P_inj, Q_inj](t) - [P_inj, Q_inj](t-1)) / scale_t[b].
    The difference is divided before it is rounded to float32, as the writer does (`generation.write`)."""
    sw = np.zeros((nx.shape[0], 2), np.float32)
    sw[metered, 0] = (nx[metered, 1] - prev[metered, 1]) / scale_t[metered, 0]
    sw[metered, 1] = (nx[metered, 2] - prev[metered, 2]) / scale_t[metered, 1]
    return sw
```

The rules: the name is the operation, not the caller; the first line of the docstring names the
quantity and cites the key with its equation number; the equation follows in plain text, with the
shape and unit of the result; the docstring is one to three lines (a few more when the equation
needs them) and says of an argument only what its name and type do not; the function is pure (numpy in, numpy out, no I/O, no dataset
objects); one test checks it on a case small enough to verify by hand.
