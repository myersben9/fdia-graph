    Modules¶

    What every folder of the repository holds, then what every Python file does, in one line: the first paragraph of its docstring. Generated by tools/layout.py; edit the docstring (or REPO and DOCS in the tool), not this page. The package section names each file by its module under fdia_graph (se.base is src/fdia_graph/se/base.py).

    The repository¶

    folder what it holds
    src/ the package fdia_graph: everything a user installs
    tests/ the test suite
    examples/ scripts a user copies: the quickstart, the training examples, the New York extension points
    results/ the results store: data only (one CSV per experiment and runs.csv), with the queries the docs read it through
    pipelines/ the builds of released data: the New York pool and timeline, and the MATLAB reference they are checked against
    tools/ repository tooling only: the gates, the generated docs, pull requests and releases
    docs/ the documentation, one folder per kind of page
    docs/getting-started/ tutorials: a first run, start to finish
    docs/guides/ how to do one task
    docs/concepts/ explanations: how a part is built and why
    docs/analysis/ one page per study with its figures: what was measured, on what, and the result
    docs/reference/ facts to look up: the file map, the data dictionary, the glossary, the formulas, the references
    docs/figures/ the images pages share, each with its data or its diagram source
    .github/ the CI workflows and the dependency updates

    The package¶

    file what it does
    fdia_graph fdia-graph — load & generate ML-only dangerous FDIA localization datasets (realistic measurement graphs).
    _lazy Public names that load on first use, for the nygrid packages.
    dataset FdiaGraph: a PyTorch-ready dataset over one HDF5 file, a timeline (one row per frame in time order, kind="timeline").
    dataset.base The loader's shared state and the constants its concerns read.
    dataset.clients The timeline as federated clients: each utility sees only its own meters, buses and labels.
    dataset.export A whole split at once: summary, and the arrays/tensors/frames of every kept record.
    dataset.graph The static graph of a shard: connectivity and the per-branch and per-bus physics, as tensors.
    dataset.physics The admittance matrices built from the static graph, and the clean power flow on every branch derived from the clean state through them.
    dataset.records One record at a time: unit conversion, __getitem__ in dict/PyG form, collate, and a ready DataLoader.
    dataset.sequence The timeline as sequences: sliding windows over a time-ordered view, and the episode table.
    download Fetch built-in shards from the GitHub Release and cache them under ~/.cache/fdia_graph.
    engine The generation engine — the math/physics/theory half of the SDK, behind fg.generate().
    engine.attacks Every attack the generator builds, behind one mixin: AttackMixin, mixed into FdiaGenerator.
    engine.attacks.area The attacker's area: the subnetwork a stealthy attack re-solves, and the boundary it holds true.
    engine.attacks.attacker The attacker: the local subnetwork it re-solves, and the false states its two goals imply.
    engine.attacks.episodes What one episode attacks: its design, drawn at onset by the family's designer.
    engine.attacks.false_state The local false state of a stealthy attack: the attacker's area re-solved under false loads with the boundary held true, checked against the operating limits, and the attack vector it writes.
    engine.attacks.family What one attack occupies on the timeline, and the interface its two families share.
    engine.attacks.interface The overload attack on a NYISO interface (N48, N49, ours): Am with OpfFdia's false states and every one of its bounds, the goal moved from one branch's rating to the flow across an interface.
    engine.attacks.minimize The cheapest support of an attack window [WU26 eq. 12].
    engine.attacks.msfdia Am, the multi-snapshot overload FDIA of [1] (TSG 2026, eqs. 12-25): over a window of snapshots the reported apparent flow of one or two target branches is driven to their ratings, each snapshot the reading of one AC false state so the operator's residual test stays quiet, while the true flow is below the rating. The attack tampers the fewest distinct meters (eq. 12).
    engine.attacks.opf The overload attacks with the attacker's false states from a local optimal power flow (N35, ours).
    engine.attacks.overload Am, the multi-snapshot overload attack of [WU26]: the reported flows of its target branches (two by default, as the paper's case studies overload two lines at once, or one; OverloadSettings.n_lines) driven to their ratings over the window, with the fewest devices tampered.
    engine.attacks.ramp At, the slow ramp: a false load that rises a little each frame, every step below the natural five-minute load swing, so no single snapshot looks anomalous while the total drifts the state away.
    engine.attacks.rref [WU26]'s own construction of the attack's support: row reduction of the transposed attack-area Jacobian with column exchanges.
    engine.attacks.stealthy The stealthy ramp At: one scan at a time, a local false state added to the true scan.
    engine.base Shared state contract for FdiaGenerator's mixins — attribute + cross-method annotations only.
    engine.core Dataset generation engine (attack simulation + realistic measurement emission).
    engine.measurement Measurement emission: turn a grid state into meter readings (the measurement function h(x)).
    engine.pandapower_types The pandapower objects the engine reads, as types.
    engine.physics A scan's load and generation, read from its stored state.
    engine.records One scan of the timeline writer: a benign scan, or an attacked At scan built by engine.attacks.
    engine.sensing The meters: what each client measures, and how wrong each meter is.
    engine.sensing.measure The measurement function: the meter readings a grid state gives, and their derivatives.
    engine.sensing.meters The meter plan: every meter on the New York buses as one row of a table, with its owner and accuracy class.
    engine.sensing.noise Meter noise: the accuracy class of each meter split into a constant bias and a per-scan jitter.
    engine.solvers The optimization solver every nygrid OPF runs on, found and checked in one place.
    errors Every error the package raises on purpose, in one place.
    federated Federated training over K clients (utilities) that never pool their records [FED26].
    federated.aggregate Averaging torch state dicts across clients with formulas.federated.fedavg [MCM17].
    federated.localizer Federated per-bus localizers: the paper's BusMLP and BusCNN trained by FedAvg over K clients [MCM17], [FED26], with records never leaving a client.
    federated.partition The split of a system's buses into K clients (utilities) for federated training [FED26].
    federated.se Federated fitting of the state estimator's learned part [EST26], [FED26].
    federated.utilities Federated clients: each NY bus belongs to the electric utility whose service territory holds it.
    formulas The mathematics of the package as named, pure functions: numpy in, numpy out, no files, no dataset objects, no torch. Each function carries its equation and a source key from docs/reference/REFERENCES.md; docs/reference/FORMULAS.md is the catalogue.
    formulas.attacks Attack shapes defined by the dataset [DAT26] that are pure functions of their parameters.
    formulas.estimation Weighted least squares state estimation and its robust variants, one function per equation [SCH70], [HAN75], [HUB64], [EST26].
    formulas.federated Statistics that combine across federated clients without moving their records [FED26].
    formulas.linalg Numerical linear algebra the estimators lean on: a guarded inverse of a normal matrix, its condition number without an eigen-decomposition, and per-record normal matrices in sub-batches.
    formulas.metrics Per-bus localization metrics from confusion counts, so they can be summed across clients or thresholds before any ratio is taken [KEC25].
    formulas.network The AC network model: branch admittances, bus injections and branch flows [AE04, ch. 2], [MP19].
    formulas.noise The meter error model: accuracy-class standard deviations split into a constant per-meter bias and a per-scan jitter [ASP14], our split.
    formulas.projection Projections through the measurement Jacobian: the explained and unexplained parts of a measurement change, leverage, the weak directions, and the meter-to-bus aggregation of the Jacobian-informed features [JAC26], [HAN75].
    formulas.temporal The temporal features of a scan [FED26]: the one-step injection change and its z-score against the bus's typical recent change, and the recent-change scale itself.
    formulas.trust Trusted-meter selection against stealthy attacks [WU26]: the attack subspace a secured set leaves open, the cost of the cheapest attack in it, and the greedy selection that closes it.
    generation generate(system, name, **knobs) — build a custom dataset and register it as name.
    generation.design The design stage of a timeline: the overload Am episodes of a split, designed before it is walked.
    generation.emit The emit stage of a timeline: every frame in time order, benign or under its episode's design.
    generation.nygrid The New York system: NYgrid's NPCC-140 case made solvable in AC, its reduced network, the 2019 loads by bus, the hourly dispatch and the five-minute pool of AC operating states, and the timeline written from them.
    generation.nygrid.build The production build: the inputs fetched at their pinned versions, and the TimelineBuilder with every decided bound (N8, N27 to N49) in one place.
    generation.nygrid.case The grid as one frozen record of arrays.
    generation.nygrid.config Build settings and the one place random generators are made.
    generation.nygrid.dispatch Hourly unit dispatch, NYgrid's allocation of the NYISO fuel mix to the fixed unit list.
    generation.nygrid.fixes The changes that make NYgrid's operating points solvable in AC (checked in MATLAB on 8760 hours of 2019).
    generation.nygrid.inputs Historical inputs: NYgrid's hourly 2019 tables and NYISO's 5-minute zonal load.
    generation.nygrid.interfaces NYISO's internal transmission interfaces on the reduced case, with their real 2019 hourly limits and flows.
    generation.nygrid.io HDF5 files of the build. The only module that imports h5py.
    generation.nygrid.load_fit How the within-hour terms of LoadModel were fitted (N31): the fluctuation's spread and autocorrelation on the real zones of a held-out year (fluctuation_fit), and industrial switching on zone D's large steps (switching_fit). Their results are the FLUCT_* and SWITCH_* constants of loads.py; run these again to refit them on other data.
    generation.nygrid.load_metrics How a load series is compared with the real one (LoadModel.validate): the load factor, the distribution of the load and of its five-minute steps, the hourly autocorrelation and the spectrum.
    generation.nygrid.load_sources Where the bottom-up load profiles come from ([LI21]), each downloaded once into a cache: the NREL ResStock and ComStock county profiles, each utility's EIA-861 sector sales, the census county centroids and the IAC industrial plants, with the clock rules the plants run on. LoadModel (loads.py) builds the bus profiles from these.
    generation.nygrid.loads Per-bus load profiles by the bottom-up method of [LI21], scaled to the real zone load.
    generation.nygrid.network Admittances of a Case, built once, and the AC quantities they give for any state, from the SDK's network formulas (formulas.network).
    generation.nygrid.npcc Read NYgrid's NPCC-140 case and apply NYgrid's own modifications (modifyMPC.m).
    generation.nygrid.pool The pool: one AC operating state per 5-minute frame, from a ramp-constrained real-time dispatch (N32).
    generation.nygrid.ratings Branch ratings from the limits NYgrid itself sets. npcc.mat carries no branch ratings.
    generation.nygrid.solver AC solutions of a Case: the hourly projection (an AC-OPF in Pyomo, solved by Ipopt), the power flows between hours (pandapower), and the operator's AC dispatch model (OperatorOpf), solved scan by scan.
    generation.nygrid.tables The CSV tables of the inputs, read whole and closed: the NYgrid checkout's bus, unit and renewable tables and the bus locations. One reader, so no input file is left open (each was a ResourceWarning before).
    generation.nygrid.timeline The timeline: the year of pool states as noisy scans, with attack episodes placed at random and labelled.
    generation.plan The plan stage of a timeline: where its splits are cut and where each split's episodes go.
    generation.write The write stage of a timeline: its datasets, columns, episodes and attributes in the HDF5 file.
    localization Per-bus FDIA localization on fdia-graph datasets, sklearn style.
    localization.base Per-bus FDIA localization on fdia-graph datasets — the shared machinery behind every method class.
    localization.learned Learned per-bus localizers: the graph-free encoders that gave the best localization numbers in the federated localization paper, on that paper's 14-dim per-bus feature vector.
    localization.methods The localizer method classes. Each changes exactly one thing about LocalizerBase — the per-bus score — so a difference between two arms is a difference between detection signals, not between calibration or metrics code.
    models Every data model of the package in one place.
    models.assets How files are found: where a dataset comes from, where its bytes are fetched from, and one line of the N-1 candidate list.
    models.base Bundle: a typed record that still IS the dict it used to be.
    models.choices Every argument that takes one value from a fixed set, in one place.
    models.config The settings every consumer accepts, one model each, checked when built (models.validation).
    models.data What a user gets back: one record, a batch, a whole split, a summary, the episode table, and the per-record truth an estimator is scored against. Each is a Bundle, so it is still the dict it always was.
    models.errors The named errors of conditions only the data reveals, beside ConfigError so a model can raise one (Validated.error), and the one error of an environment that cannot run a step (SolverUnavailable). fdia_graph.errors re-exports every one.
    models.federated What the federated layer passes around: how the buses split into clients.
    models.fields The field groups the data bundles share.
    models.frames What the generator passes around per scan: a measurement scan, the emitted frame with its labels, the run's attack knobs, the design of an At ramp and of an Am overload episode, and what the fewest-tamper search returns.
    models.grid The static description of a system: the per-branch pi model and the admittance matrices built from it, which meters exist, the constant meter bias, and the N-1 contingency a generator was built with. Nothing here changes from one scan to the next.
    models.inputs What the formulas and the parsers accept, one model each, checked when built (models.validation).
    models.plan The records of a timeline's plan and design stages: a placed episode (Slot), a split and its frames (SplitSpan), an episode not yet written (Pending) or designed (Designed), what is placed (Schedule) and what the placement asked for and got (Placement), and what a design worker rebuilds its generator from (GeneratorSpec).
    models.results The models of a results table: the metric registry, a Record (one measured value with the keys that say what it is) and a Provenance (which run made it), plus the parsers that read loose input (a nested score report, a filter value, a run's settings) by its type. Every check lives here, per the validation rule, so a store never holds an unknown metric, a non-finite value or a malformed key; fdia_graph.results builds these models and never checks its input itself.
    models.scores The result tables: an estimator's error pair per record class, a localizer's metric rows per class, and the Jacobian feature outputs. Each is a Bundle, indexable by family name as before.
    models.training What the learned localizers pass between their fitting pieces (a centralized fit and a federated client share them).
    models.validation The one place inputs are checked (CONTRIBUTING.md, "an input is checked in one place").
    operator The grid operator under attack: what it does with false readings, and what that costs on the true grid.
    operator.acsced The operator's real-time dispatch as an AC optimal power flow (AcSced), scan by scan.
    operator.areas Who bears an attack's damage, and whose grid the attacker uses: the consequence split by New York zone, by utility and by neighboring area, with what the attack tampered in each.
    operator.day An attacked day as the operator meets it: the scans it reads and their benign twin, the true states, the pool's unit dispatch and costs, the zonal prices, and the interfaces with their real limits (operator_day).
    operator.policy The operator's choices as one record (OperatorPolicy): which operator (OperatorMode), how late it acts, where the inadvertent interchange its neighbours supply enters (Entry, entry_share), whether it reads the true flows after its own dispatch, and how it answers an alarm (AlarmAnswer). The record checks every choice when it is built, so a typo is a ConfigError before anything runs.
    operator.run The operator scan by scan (D1 to D6). It dispatches on what it reads (AcSced), the attacked scans and, separately, their benign twin, each in closed loop on its own dispatch. The dispatch is applied to the true grid, whose load the attack never changed: the imbalance it leaves is picked up by regulation, the online free units in proportion to their five-minute ramp (AGC), up to REG_CAP, and the rest by the neighbours as inadvertent interchange. The attack's consequence is the attacked run less the benign one, so whatever the model does alike in both (the cost model) cancels. respond runs both and returns the Response.
    operator.summary The attack's consequence over a day, attacked run less benign run (summarize): the dispatch moved, the regulation and its energy by utility, the inadvertent interchange, the true interface changes and margins, the scans over a true limit and those whose power flow failed, the costs, and any load shed.
    operator.ties The interchange check: what the operator reads across the ties against what the neighbours' own meters read (N62, N67). The New York ends of the ties carry the attack's false interchange, the neighbours' ends do not, so the gap between them (tie_gap) leaves its benign noise once an attack moves the interchange, and interchange_alarm names the first scan it does. seen_interfaces is the interface flow the operator reads from its own scans.
    operator.truegrid The true grid of a day: what the operator's actions do to the flows the attack never changed. An AC power flow at the true loads for any unit dispatch (TrueGrid.state), the true state once a run has acted (run_state, the closed loop), and the interface flows and the worst single 345 kV outage it gives (change). A power flow that fails returns None and its scan is unknown, never safe. Each outage is screened by an AC power flow of the grid without the branch (ac_power_flow).
    profiles Load-profile ingestion + operating-state generation — the FRONT of the pipeline.
    ratings Branch thermal ratings for the overload attack of [WU26] (eqs. 24-25), stored with the package.
    registry Dataset registry: built-in (downloadable) datasets + locally generated ones.
    results Measured results as data: typed records with their provenance, one tidy store, and the renderers that put the numbers into docs and figures, so no measured number is typed by hand.
    results.docs Measured numbers in markdown come from the store, never from a keyboard.
    results.render Turning records into what a reader sees: a formatted cell, a markdown table, a pivot of records by two keys, and the CSV sidecar a figure is drawn from. Nothing here measures or stores anything.
    results.run How a harness records what it measured: open a Run, add values, and the run writes them to the store with its provenance when it closes.
    results.store The results store: one tidy CSV per experiment plus one table of runs, in a folder kept in git.
    results.studies Studies over attack windows: the parts every research tool under pipelines/newyork/ repeats, in one place.
    schema The file protocol: every group, dataset and attribute name an fdia-graph HDF5 file carries, defined once. The writer (timeline, generation), the readers (dataset) and the tools agree through these names and nowhere else; tools/readability.py refuses a path-shaped literal ("data/...", "graph/...") in any other module. Field names (node_x, clean, ...) are the public vocabulary of a record and stay as words in the code; FIELD_PATH maps them here.
    se State estimation on fdia-graph datasets, sklearn style.
    se.base State estimation on fdia-graph datasets — the shared machinery behind every method class.
    se.detect Detection: what the operator's checks see, as building blocks.
    se.detect.estimate The operator's state estimator: AC weighted least squares on one scan, and its residual test statistic.
    se.detect.fleets Other meter fleets: the same meters and accuracy classes with fresh constant biases.
    se.detect.rules When a detector alarms: the rule that turns a statistic per scan into a first alarm.
    se.jacobian Jacobian-informed features (Abdulin & Narimani): the measurement Jacobian as a physics transform of the scan-to-scan measurement change, not as raw model input.
    se.methods The estimator method classes. Each changes exactly one thing about SEBase, so a difference between two arms is a difference between estimators rather than between implementations.
    timeline One continuous attacked timeline per system, written as one HDF5 file.
    trust Which meters to trust so that stealthy attacks stop being stealthy [WU26], sklearn style.
    trust.base The shared machinery of the trusted-meter selectors: the measurement Jacobian at the benign mean (from a WLS estimator of fdia_graph.se), the attack-cost kernel, and the scoring that pins the secured meters and asks the residual test whether the attack shows.
    trust.faithful_attack [WU26]'s attack and defense as the paper states them (docs/analysis/defense_reproduction/README.md, "Faithful reproduction"): the meter plan, the multi-snapshot attack and the incremental trusted-PMU defense, on a pandapower case.
    trust.faithful_defense [WU26]'s trusted-PMU defense on the faithful attack (trust.faithful_attack): the MDP (Sec. IV-D2, Fig. 1, Algorithm 1) and Solution 1's row reduction (Sec. IV-D1, p. 657).
    trust.meter_dqn The trusted-meter selection as a Markov decision process solved by a deep Q-network (the learned selection of [WU26]).
    trust.pmu_dqn [WU26]'s Solution 2: the trusted PMUs by a deep Q-network trained with Algorithm 1 (Sec. IV-D2, p. 658) on trusted-PMU MDPs (trust.WuDefenseEnv).
    trust.pmu_environment [WU26]'s trusted-PMU configuration as a Markov decision process (Sec. IV-D2, Fig. 1, Algorithm 1), on the overload attack of one window.
    trust.pmu_row_reduction [WU26]'s Solution 1: the trusted PMUs by row reduction of the measurement matrix (Sec. IV-D1, p. 657), on the trusted-PMU MDP of one overload window (trust.WuDefenseEnv).
    trust.secured A copy of a timeline with a set of meters secured: the attacker locked out of them, so on every frame their observed reading is the benign one, and the stored temporal features recomputed from the pinned observed frames (timeline.write_temporal_layers). The estimators and the localizers then read the copy like any timeline, which is how a trusted-meter selection is measured on state estimation and localization rather than on the residual test alone (TrustSelector.score). The copy is rewritten in blocks of frames, so a 72,000-frame timeline of any ladder system fits in bounded memory.

    Tools¶

    file what it does
    tools/bench.py Time the estimators and the generator on the tiny timeline, and store the timings as a run of the bench experiment in the results store (results/bench.csv), where docs/reference/BENCHMARKS.md renders them from (a results block).
    tools/class_diagrams.py Write the class and module diagrams of the package from its source, as Mermaid sources under docs/figures/diagrams/, so the pictures in docs/reference/CLASS_MAP.md never drift from the code.
    tools/layout.py The repository's layout rules, and the file map they keep current (docs/reference/MODULES.md).
    tools/models_doc.py Render the public data models into docs/reference/DATA_DICTIONARY.md.
    tools/pr.py Pull requests from the command line, without the gh CLI (CONTRIBUTING.md, "The pull request").
    tools/prereview.py Every check a pull request must pass, run locally in one command before the review is requested (CONTRIBUTING.md, "The pull request").
    tools/readability.py Readability measures for src/fdia_graph, the limits below (LIMITS), and the file-protocol rule: a dataset path ("data/...", "graph/...", any group of schema.Group) or a group name used as one (f.create_group("data"), f["attack"], "episodes" in f) may be spelled only in src/fdia_graph/schema.py; every other module goes through schema. And the validation rule (CONTRIBUTING.md, "an input is checked in one place"): raise ValueError / raise TypeError and isinstance(...) only inside fdia_graph.models, where the one engine checks every input and the parser models read loose input by its type; everywhere else an input is checked or parsed by building its model, and a condition only the data reveals raises a named error from errors. And the typing rule: an annotation says Any only where ANY_ALLOWED lists it with the reason the value can be anything; every other annotation carries its real type.
    tools/release.py Cut a package release after the version-bump PR has merged (CONTRIBUTING.md, "Releasing").
    tools/render_mermaid.py Render a Mermaid source file to a standalone SVG and a PNG next to it. Every diagram in the docs is such a rendered image, because the README is also the PyPI page and the docs are read in the GitHub mobile app, and neither renders a Mermaid block.
    tools/results_docs.py Fill and check the results blocks of the docs from the results store (results/).
    tools/site_index.py Stage the three root pages of the repository for the docs site: README.md becomes docs/index.md, CONTRIBUTING.md docs/contributing.md and CHANGELOG.md docs/changelog.md. The README is the single source for the landing page; its links carry a docs/ prefix that is wrong once the file lives inside docs_dir, so the prefix is stripped on copy, and links between the three root pages are rewritten to their staged names. Runs in the Vercel build (vercel.json) and in the versioned deploy (.github/workflows/docs.yml); the three staged files are generated output and stay untracked.
    tools/upload_assets.py Publish data-release assets to a GitHub release (CONTRIBUTING.md, "Releasing", data releases).

    Tests¶

    file what it does
    tests/conftest.py Shared fixtures. The suite builds its own tiny IEEE-14 timeline (about 20 s, needs the [generate] extra and the operating-point pool download) inside a throwaway cache, so it never touches a user's ~/.cache/fdia_graph and never downloads a full timeline. Old releases are read from the checked-in files under tests/data (tests/data/README.md).
    tests/digests.py Whole-file digests of a generated HDF5 file: the proof that a refactor did not move a number.
    tests/nygrid/conftest.py The New York tests' shared setup: the operator's dispatch reads the bus reactive loads of the checked-in days.
    tests/nygrid/inputs.py The inputs of the nygrid tests in one place, and which tests each one lets run.
    tests/nygrid/test_areas.py The damage split by area adds up to the whole: the zones and the utilities each partition New York's units, the neighbors' supply is the inadvertent interchange, and the attack surface counts the meters the day's labels mark.
    tests/nygrid/test_attacks.py The New York attacks on the real grid: the attacker's area and false states, the multi-snapshot overload (MsFdia), the ramp, and that each meets its goal, stays within the natural load swing and evades the residual test.
    tests/nygrid/test_build.py The release builder's attacker sensitivities stay with the attacker: a timeline built with v_margin records the case's true voltage limits, while the attacker designs against the widened ones (N71). Needs the public inputs and the whole 2019 pool (inputs.py).
    tests/nygrid/test_choices.py The operator's choices are checked before anything runs: a typo is an error, never a silent fall back to the default run (no data needed).
    tests/nygrid/test_configs.py Settings are passed in, never patched onto shared objects: a widened case and an overshoot variant are copies, and the originals stay as they were (no data needed).
    tests/nygrid/test_dataset.py The timeline file as federated clients (dataset.clients): a written file reloads whole, each client sees only its own meters, buses and labels, and the operator and split views select the right frames.
    tests/nygrid/test_detect.py The detection building blocks that need no grid: the persistence rule and its calibration, and the meter fleets (the estimator itself is checked on real days by the golden snapshots).
    tests/nygrid/test_examples.py The extension examples of docs/guides/extending_new_york.md run as published, so the guide never shows code that broke (no data needed).
    tests/nygrid/test_experiments.py The study helpers every research tool shares: the day files of a study, a day's variant, the interchange calibration, and the parallel runner that writes a sorted CSV (no data needed).
    tests/nygrid/test_golden.py Golden snapshots of nygrid's outputs on fixed inputs, the safety net of the readability refactor.
    tests/nygrid/test_grid.py The New York grid as read from NYgrid: the NPCC case and NYgrid's modifications, the fixed unit list, the AC fixes, the utility of each bus and the branch ratings, checked against MATPOWER's power flow.
    tests/nygrid/test_misses.py Every design that finds no attack says why (MISSES), so a timeline with few attacks can be read: nothing to attack, nothing feasible, or a solver that failed (no data needed).
    tests/nygrid/test_operator.py The operator's real-time dispatch (operator.acsced, an AC optimal power flow each scan): the 2019 shortage price, the delivery factors and AC sensitivities, the outage power flow, and the operator on days under attack.
    tests/nygrid/test_policy.py The operator's choices are one validated record, and an operator is anything that returns a Response (no data needed).
